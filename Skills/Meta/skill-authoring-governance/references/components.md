# Skill Components Reference

Use this reference when deciding what belongs in `SKILL.md` versus `references/`.

## Keep in `SKILL.md`

- Trigger conditions
- One short workflow
- Decision tree
- Non-negotiable guardrails
- Related skills map

## Move to `references/`

- Full implementation examples
- Extended architecture patterns
- Edge case catalogs
- Anti-pattern inventories
- Migration guides

## Component Checklist

- Is the section needed in every invocation? Keep in `SKILL.md`.
- Is the section optional or topic-specific? Move to `references/`.
- Is the section long (>30-40 lines)? Prefer `references/`.
