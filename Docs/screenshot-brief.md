# Alike Screenshot Brief

The production brief for the App Store screenshot deck: what each slide says,
where its parts sit, and what has to be true before it ships.

For the *capture* side — devices, sizes, locales, the import pipeline and the
per-shot status table — see `Docs/screenshot-shot-list.md`. For the copy and
visual rules behind the decisions below, see
`Skills/DesignConcept/app-store-screenshots/SKILL.md`.

Source of truth for everything here is `SLIDES` and `COPY` in
`tools/generate_app_store_product_screenshots.py`. This document explains the
intent; the script is what actually renders.

## The deck

Five slides, in listing order. Each is 1320 × 2868 on a dark canvas that matches
the app's own appearance: one label, one headline, one supporting line, and a
tilted iPhone carrying the capture.

| # | Capture | Composition | Band | Job |
|---|---|---|---|---|
| 1 | `01-scanner-idle` | caption top, left, phone bleeding off the bottom | accent | What the app is, and that it runs on device |
| 2 | `03-cleanup-queue` | caption bottom, right, complete device above | purple | There is a queue, and progress is visible |
| 3 | `04-cluster-details` | caption top, right, phone bleeding off the bottom | accent | The keeper is chosen for you |
| 4 | `05-comparison-review` | caption bottom, left, complete device above | purple | Nothing is deleted without review |
| 5 | `07-cleanup-progress` | caption top, centre, phone bleeding off the bottom | green | The payoff — space comes back |

Two compositions alternate so the deck reads as a rhythm rather than five of the
same frame, and neither one shows the empty lower half of a capture.

The three band colours are the app's own: `accent` is the teal of the Start
Scanning button, `purple` is the mascot, `green` is freed space. The green lands
on the last slide because that is the one about storage returned.

## Copy

Per locale, per slide: a short uppercase label, a two-line headline, and one
supporting sentence. Wording tracks the listing description generated by
`tools/prepare_app_store_upload_bundle.py` — if the description changes, these
change with it.

Seven decks, one per listing localization. The directory names are the app's own
language codes, so `es-419` and `pt-BR` — `tools/prepare_app_store_upload_bundle.py`
maps `es-419` onto App Store Connect's `es-MX` slot on the way out.

Copy rules that the renderer will not catch for you:

- No prices anywhere. StoreKit supplies localized pricing; a number baked into
  an image goes stale and contradicts the store.
- No claim the published legal text does not support. On-device Vision, no
  uploads, no account, confirmed deletion into Recently Deleted — those are in
  `Docs/legal/` and the listing description, and the slides must agree.
- Several languages run longer than English — Ukrainian, German and Portuguese
  in particular. `fit_font_size` shrinks until the copy fits, so an over-long
  line silently costs type size rather than breaking the render. Check the
  output for every locale, not just the exit code and not just `en-US`.
- The `\n` in a headline is a per-language decision. German does not break where
  "Find the photos / that look alike" breaks; pick the point that keeps both
  lines balanced in that language.

## Background variant

Four variants share the same concept. The listing ships `spotlight`.

```sh
build/tools-venv/bin/python tools/generate_app_store_product_screenshots.py --drafts
```

renders all four into `build/generated/product_screenshot_drafts/` with a
comparison contact sheet. Choosing a different one is a `--variant <name>` run
into `Docs/images/`, and a one-line change here.

## Rendering

```sh
python3 -m venv build/tools-venv && build/tools-venv/bin/pip install --upgrade pip Pillow
build/tools-venv/bin/python tools/generate_app_store_product_screenshots.py
```

Pillow is not in the system Python, so the venv is created once.

## Adding a slide

The App Store allows ten screenshots; five ship, so there is room. Adding one
means, in `tools/generate_app_store_product_screenshots.py`:

1. A `SlideLayout` in `SLIDES` — pick the composition that continues the
   alternation, and a band colour that matches what the slide is about.
2. One `(label, headline, subtitle)` tuple per locale in `COPY`, at the same
   index. The generator refuses to run if any locale is short an entry.
3. The capture itself, at 1320 × 2868 in `Docs/images/raw/<locale>/`.

Captured-but-unused shots — 2, 6, 8, 13 — are the candidates. Shots 10 and 11
are App Review evidence and deliberately stay out of the listing.

## Before upload

- All seven locales rendered and eyeballed, not just generated. Type size in the
  long languages — uk, de, pt-BR — is the usual casualty.
- Headline and supporting line legible at App Store thumbnail scale.
- No status-bar noise: full signal, full battery, no notifications.
- Privacy sweep on any *new* capture — recognisable faces, location giveaways,
  readable personal data, anything legible on a screen shown inside a photo.
  The existing frames have been reviewed and accepted as they are.
- `tools/upload-screenshots` for the upload; see `Docs/ci-cd.md` for the
  duplicate-upload behaviour.
